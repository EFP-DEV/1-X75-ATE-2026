# Identite du projet

**Durée** : 4h
**Objectif** : définir le projet avec assez de précision pour enchaîner sur les wireframes en session 2.

Pas de code. Décider et écrire.

---

```

Public cible :

- Action recherchée :

Objet principal (item) :
(entité centrale du site — concept métier, pas une table BDD)

Objectifs :

- Admin : permettre à un administrateur de...

Fonctionnalités principales :
-
-

Pages prévues :
- Publiques :
- Admin :
```

**Règles de rédaction**

- Formulations vagues interdites : "un site moderne", "un site pratique", "un site pour tout le monde".
- Formulations exploitables attendues : "catalogue de produits avec fiches détaillées", "site MVC avec espace public et back-office d'administration".
- Un objectif décrit une action permise, pas un adjectif.
- Public cible ≠ "tout public" : répondre aux trois sous-questions du champ.

---

## Livrable 2 — Mini analyse concurrentielle

Observer 3 sites minimum proches du sujet.

Pour chaque site :
- URL / nom
- Intérêt par rapport au projet
- 1-2 points réussis
- 1-2 points faibles
- Ce qui est retenu pour le projet

Axes d'observation : navigation, clarté page d'accueil, organisation des fiches détaillées, lisibilité des menus, hiérarchie visuelle, facilité à trouver l'info, surcharge éventuelle.

Exemple de remarque exploitable : "navigation simple et claire, je retiens l'idée d'un listing avec filtres."
Exemple à éviter : "site bien fait."

---

## Livrable 3 — Repository initialisé

- Nom clair
- Arborescence de départ simple
- Premier commit propre, message explicite
- Dépôt partagé selon consignes du cours

Pas de fichiers inutiles, pas de commit vide.

---

## Livrable 4 — README.md

Contenu minimal :
- Nom du projet
- Thème
- Description courte
- Public visé
- Objectifs principaux

Cohérent avec la fiche de cadrage. Compréhensible sans autre source.

---

## À ne pas faire

- Charte graphique, logo, couleurs
- HTML / PHP
- Intégration avant d'avoir fixé les pages
- Fonctionnalités sans objectif défini
- Périmètre trop large pour le temps du projet

---

## Minimum en cas de retard

- Sujet clair
- Public cible identifié
- Liste de pages
- Repository créé
- README commencé

---

## Checklist de fin de séance
